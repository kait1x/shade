## 2. Автоматические проверки (этот worktree)

### Browser QA (`server/tools/alpha-browser-qa.mjs`, 2 движка)

Реальный HTTPS/WSS, реальный WebCrypto, независимые постоянные профили,
viewport **390×844, isMobile, hasTouch** (мобильная геометрия). Полный сценарий:
регистрация → сверка отпечатков → двусторонняя E2EE → offline reload + outbox →
reply → deleteLocal → typing → read-ACK → медиа-чанки → Избранное → профиль v2 →
стикеры/подарок → push → **PWA shell (новое)** → длинные сообщения + скролл →
клавиатура (480px viewport) → overflow-sweep 320/390/430/768/1440.

Новые проверки PWA shell (добавлены 17.11.2026):
- `GET /alpha-manifest.json` → 200, `application/manifest+json|json`, name `Shade`,
  `display: standalone`, `start_url: /`, `scope: /`, ≥3 иконок;
- все иконки manifest + `apple-touch-icon.png` + `favicon.png` → 200, `image/png`;
- активный Service Worker контролирует страницу после `clients.claim()`;
- кэш `shade-alpha-*` содержит `/alpha.html`, `/alpha-manifest.json`,
  `/flutter-ui/flutter_bootstrap.js` (offline shell);
- in-app «Установить Shade» (`shadeAction('install')`) открывает диалог-гайд в
  профиле.

Результат: **Edge — PASS (включая push: subscribed), WebKit — см. раздел 5.**
Важно: нативный `beforeinstallprompt` в headless движках вызвать нельзя —
проверяется гайд-путь, не промпт браузера. Это не подмена: результат помечен
как guide-путь, а не как тест установки на устройстве.

### Flutter-тесты (`client/test/web_alpha_ui_test.dart`, +3 мобильные регрессии)

- **Single-pane навигация**: 390×844 — список ↔ чат, `PopScope.canPop`
  переключается, системный «назад» (maybePop) уходит в `act('back')`, а не из
  приложения — регрессия Android-жеста назад.
- **Wide layout**: 1200×900 — список и чат сосуществуют (двухпанельность не
  регрессировала в однопанель).
- **Композер и клавиатура**: при `viewInsets.bottom = 340` maxLines 5→3, без —
  5. Примечание: в тест-биндинге Flutter 3.50 `tester.view.viewInsets` двигает
  render-поверхность, но `MediaQuery.viewInsetsOf` остаётся 0, поэтому inset
  подаётся обёрткой `MediaQuery` (проверяется логика виджета, как в реальном
  браузере).

## 3. Сборка тестового Web/PWA release

```bash
# из корня worktree
flutter pub get --directory client        # если ещё не выполнено
python client/tools/build_web_alpha.py    # Flutter UI → client/build/web-alpha + cache-files.js
python client/tools/assemble_pwa_release.py  # единый каталог → client/build/pwa-release
```

`pwa-release` = DOM-shell (`client/web`) + Flutter UI (`/flutter-ui/`, без
web-исходников, которые flutter build копирует в output) + release-manifest.json
(количество файлов, размеры, SHA-256). Сервер должен раздавать содержимое
каталога как web root и `/socket.io/socket.io.js` (это делает alpha-сервер);
SW-allowlist покрывает ровно эти файлы. Текущая сборка: 57 файлов, 50.4 МБ,
SHA-256 `c5424fb4…476883`.

## 4. Пошаговая проверка на Samsung Galaxy A25 через Chrome

Требования: staging HTTPS-адрес из `docs/IPHONE_PWA_STAGING.md` (раздел 2/6),
два устройства/аккаунта для сверки отпечатков. Galaxy A25: Android 14+, Chrome
стабильный. Это физическое устройство — автоматически эмуляция не покрывает
только шаги 12–14 (нативный промпт и реальный push-канал).

1. **Подготовка.** На ПК сохраните recovery-пакет тестового аккаунта. На
   телефоне включите интернет, откройте **Chrome** (не Samsung Internet —
   проект валидирован на Chrome; Samsung Internet не тестировался).
2. **HTTPS-вход.** Откройте staging-URL. Убедитесь: адрес `https://`, зелёного
   замка не требуется (нужен доверенный сертификат: Tailscale Funnel/
   Cloudflare). На `localhost`-туннелях Chrome не потребует исключений.
3. **Регистрация.** «Войти через Google» → выберите тестовый Google-аккаунт →
   создайте имя пользователя → задайте **фразу устройства** (≥16 символов) и
   **recovery-фразу** (≥24, отличную от первой) → «Создать ключи на этом
   устройстве». RSA-4096 занимает до минуты — не закрывайте страницу.
4. **Recovery-пакет.** «Скачать recovery-пакет» → файл появится в
   «Загрузки». Отметьте чекбокс → «Завершить регистрацию» → статус
   «Подключено · E2EE» внизу списка чатов.
5. **Установка PWA.** Меню Chrome (⋮) → **«Установить приложение»** (или
   баннер установки, если Chrome предложит; кнопка «Установить Shade» в
   профиле открывает тот же промпт). Подтвердите. Иконка появится на домашнем
   экране; в лаунчере — отдельное приложение «Shade».
6. **Standalone.** Запустите Shade с иконки: нет адресной строки и панелей
   Chrome, статус-бар чёрный (theme-color #000). Клавиатура не должна
   уводить нижний край композера под панель жестов.
7. **Клавиатура.** Откройте чат с собеседником → коснитесь поля «Сообщение»:
   композер остаётся видимым над клавиатурой, список не прыгает без причины;
   вводите 5+ строк — поле растёт до 3 строк при открытой клавиатуре.
   Сверните клавиатуру жестом назад — композер вернётся.
8. **Жест «назад».** В чате системный жест назад возвращает к списку чатов
   (не закрывает приложение). Со списка — закрывает/сворачивает.
9. **Прокрутка.** Отправьте 30+ сообщений с ПК; прокрутите историю на телефоне:
   разделители дат, длинные сообщения переносятся без обрезки; FAB «К последним»
   появляется при отходе вниз (вверх по списку), счётчик непрочитанных при
   новых сообщениях, тап — плавный возврат к свежим.
10. **Offline.** Включите авиарежим: статус «Нет сети · история сохранена»;
    перезапустите приложение с иконки — экран разблокировки работает офлайн,
    после фразы доступна зашифрованная история и «Повторить» в футере.
    Отправьте сообщение в авиарежиме — уйдёт в очередь (часы 🕒). Выключите
    авиарежим — сообщение доставится автоматически.
11. **Обновление SW.** После публикации новой сборки при открытии Shade
    появится диалог «Доступно обновление Shade» → «Перезагрузить и обновить».
    Без нажатия версия не меняется (ключи и история не трогаются).
12. **Push.** Профиль → «Уведомления»: системный запрос разрешений —
    «Разрешить». Уведомление-сигнал приходит при закрытом приложении
    (требуется работающий VAPID на сервере). Отказ разрешений не ломает чат;
    повторное включение — через настройки Android → Приложения → Shade →
    Уведомления.
13. **Плохая сеть.** Включите «Экономию трафика» или ухудшите сигнал: отправка
    либо проходит с задержкой, либо показывает честную ошибку с возможностью
    «Повторить»; сообщение не теряется и не перезашифровывается.
14. **Media.** Отправьте фото из профиля редактора (композер → галерея):
    фото сжимается на клиенте (512КБ), чанками уходит в E2EE; получатель на
    втором устройстве видит изображение.

Откат/чистка: удаление иконки не удаляет ключи. Полная очистка = Chrome →
Настройки → Настройки сайтов → Все сайты → Shade → «Удалить данные» — только
после сохранения recovery-пакета (без него ключи не восстановить).

## 5. Что автоматика НЕ доказывает (честные ограничения)

- **Физическое устройство ≠ эмуляция.** Headless-движки проверяют логику и
  геометрию 390×844, но не нативный промпт установки, не реальный FCM/push
  транспорт Android, не поведение браузера Chrome на Samsung One UI.
- **Физический iPhone не тестировался** — требуется шаг по
  `docs/IPHONE_PWA_STAGING.md` (раздел 4); WebKit-блок отложенного flush
  IndexedDB при мгновенном перезапуске проверен только в headless.
- **Samsung Internet, Firefox Android, браузеры Samsung One UI** — вне
  охвата; PWA-контракт стандартный, но не валидирован.
- **Настоящий Google OAuth** — QA использует синтетического провайдера;
  реальный consent-экран проверяется вручную на staging.
- **Web Push на устройстве** требует сервера с `ALPHA_VAPID_*` и публичного
  HTTPS; на LAN без доверенного сертификата подписка откажется честно.
