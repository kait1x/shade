## Важные условия миграции

1. Обновлять клиент и сервер вместе: новый клиент требует подписи key bundle версии 3. Старые ключи пользователей переподписываются при `/user` без замены моделей идентичности.
2. Перед обновлением сохранить `server/data`, сертификаты и стабильный SESSION_SECRET в приватной резервной копии. Не менять SESSION_SECRET наугад: он защищает существующие данные.
3. При первом старте новая очередь читается из legacy `offline.json`, если `messaging.json` ещё отсутствует. Затем источником истины служит единый encrypted snapshot. Старый файл не удаляется автоматически. Повреждённый канонический snapshot вызывает отказ запуска вместо молчаливого сброса очереди.
4. Идемпотентность и replay квитанций ограничены 7 сутками. Лимит журнала 10 000 записей; при заполнении сервер отказывает новым сообщениям, а не забывает ещё действующие receipt. Queue per recipient: 200 envelopes / 30 MiB; сообщение до 10 MiB.
5. Удаление ожидающей записи отменяет ещё не начатую отправку. Уже отправленный сетевой запрос невозможно «отозвать» локальным удалением; для доставленных сообщений есть отдельное подтверждаемое сервером удаление для всех.
6. Google-вход остаётся привязан к установленной идентичности/ключам устройства. Восстановление старой переписки на другом телефоне не добавлялось.

## Проверки и ограничения

Результаты финальных команд и запуска APK записаны в `artifacts/fixes/`. Стандартные наборы: 27 Flutter-тестов и 8 Node-тестов. Node-набор включает реальные TLS-соединения и отдельный процесс relay; это не тест двух реальных телефонов. Миграции выполнены на SQLite test factory; фактическое шифрование mobile проверяется SQLCipher в Android-сборке, а не FFI-фабрикой.

Не подтверждены: реальный Google OAuth, доставка FCM от Google, два физических телефона, WAN, production release с собственным signing key, iOS/Xcode, Docker runtime, аварийное отключение питания хранилища, длительный нагрузочный тест. Docker и Xcode на этой машине недоступны.

Текущий `google-services.json` содержит 0 OAuth clients, а Web Client ID отсутствует в тестовой сборке. Его нельзя выдумать. Нужны настоящий OAuth Web Client ID на сервере/в сборке и Android OAuth client для SHA подписи. Debug APK направлен на `https://10.0.2.2:3443` и предназначен для эмулятора, не для готового интернет-сервиса.

Android minimum API 24 сохранён. Требование API 23 исходного ТЗ остаётся несовместимым с текущей Flutter 3.38.10 средой и требует отдельной проверенной смены SDK/зависимостей, а не подмены minSdk.

`.env` больше не индексируется, секреты исключены из Docker/Git в дальнейшем. Удалённые/публичные значения из истории невозможно безопасно исправить только кодом: владельцу нужно ротировать действовавшие секреты и согласовать очистку Git-истории. История не переписывалась, внешние пароли не изменялись; никакие секреты не помещены в отчёт.

Сценарии прежних файлов `artifacts/audit/*-probes.*` — историческое воспроизведение ошибок. Актуальные ожидания исправленного поведения находятся в `client/test/audit_regressions_test.dart`, `security_regressions_test.dart`, `ui_design_test.dart`, `server/test/audit-regressions.test.js`, `direct-messaging.test.js`.
